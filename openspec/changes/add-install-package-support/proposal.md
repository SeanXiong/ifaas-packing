## 为什么

当前平台仅支持打升级包，且打包记录固定查询离线升级包，无法完成安装包的提交、查询、删除和离线包网盘分发。后端已提供安装包及其记录管理接口，需要在平台中统一支持四类包的完整操作闭环。

## 变更内容

- 在开始打包后增加包族选择，允许用户选择升级包或安装包，并保留组件与分支的二次确认；确认内容展示最终包类型。
- 支持离线升级包、在线升级包、离线安装包、在线安装包四类包的提交，并按类型调用对应后端接口。
- 将打包记录弹窗改为按打包类型查询，默认离线升级包；移除搜索、状态、CPU 架构和排序控件，记录按后端返回顺序展示。
- 支持安装包记录的删除，并按安装包或升级包选择正确的删除接口。
- 仅允许离线包上传云盘；在线安装包和在线升级包强制关闭云盘上传，且记录中不提供上传入口。
- 在云盘上传进度区域展示后端返回的实时上传速度。

## 能力

### 新增能力

- `package-type-orchestration`：选择包族并将离线/在线组合为四类包，完成提交和确认展示。
- `package-record-type-filtering`：按包类型查询、展示和删除升级包或安装包记录。
- `offline-package-seafile-upload`：限定离线包的云盘上传能力，并展示上传进度与速度。

### 修改的能力

- 无。

## 影响

- 前端页面与交互：`web/index.html`、`web/js/app.js`、`web/css/app.css`。
- API 客户端：`web/js/api.js`，新增安装包提交、查询与删除资源选择。
- 本地代理：`server.py`，安装包提交需要采用与升级包相同的长请求超时策略。
- 测试：更新或补充前端逻辑测试，覆盖四类包的接口映射、在线包云盘限制和上传速度展示。
