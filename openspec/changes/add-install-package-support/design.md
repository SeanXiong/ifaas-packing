## 背景

平台由静态前端、`ApiClient` 和 Python 本地代理组成。当前打包提交、记录查询和删除逻辑均固定为升级包资源，右侧通过离线/在线单选项决定请求体中的 `offline` 字段。安装包后端资源已可用，且请求体与升级包高度一致；两类包均使用相同的云盘上传和进度查询接口。

本次变更涉及打包交互、请求路由、记录操作、云盘权限和代理超时策略，需用统一的包类型模型避免各处条件分支不一致。

## 目标与非目标

**目标：**

- 将“包族（升级/安装）”和“联网方式（离线/在线）”组合成唯一的最终包类型。
- 让提交、记录查询、删除和云盘上传均根据最终包类型执行一致的行为。
- 保留现有组件与分支二次确认，并增加包类型确认信息。
- 对在线包从控件、请求体和记录操作三层禁止云盘上传。
- 在已有上传进度条中展示接口返回的实时上传速度。

**非目标：**

- 不修改后端打包、记录、云盘上传接口及数据模型。
- 不增加新的记录分页、搜索、排序或状态筛选能力。
- 不改变组件选择、分支编辑和项目/版本加载行为。
- 不改变已生成包的下载地址、云盘地址或组件详情展示格式。

## 决策

### 使用二维包类型模型

在前端维护 `packageFamily`（`upgrade` 或 `install`）与 `offline`（布尔值），通过一个集中映射生成最终显示名称、提交路径、记录路径和删除路径。

| 最终包类型 | `packageFamily` | `offline` | 提交资源 | 记录/删除资源 |
|---|---|---:|---|---|
| 离线升级包 | `upgrade` | `true` | `/api/v1/packplus/upgrade/{versionId}` | `/api/v1/recordsprojectupdate/` |
| 在线升级包 | `upgrade` | `false` | `/api/v1/packplus/upgrade/{versionId}` | `/api/v1/recordsprojectupdate/` |
| 离线安装包 | `install` | `true` | `/api/v1/packplus/install/{versionId}` | `/api/v1/recordsprojectinstall/` |
| 在线安装包 | `install` | `false` | `/api/v1/packplus/install/{versionId}` | `/api/v1/recordsprojectinstall/` |

选择集中映射而不是在提交、记录和删除函数分别判断，是为了让新增的安装包分支可测试且避免调用错资源。

### 将包族选择放在开始打包后的第一个弹窗

右侧继续使用现有离线/在线单选项；点击“开始打包”后，先选择升级包或安装包，再进入既有的组件与分支确认弹窗。确认弹窗展示“包类型：{离线/在线}{升级/安装}包”。

该方案保留用户熟悉的联网方式配置，且避免将右侧配置区扩展为四个容易误选的单选项。

### 以在线状态强制限制云盘上传

当用户选择在线包时，前端必须立即取消选中并禁用云盘开关；构建请求时也必须将 `seafile` 设为 `false`。记录卡片仅在离线记录缺少云盘地址时显示“上传云盘”操作。

双重约束避免脚本、旧页面状态或控件失效时仍向在线包传递云盘上传参数。

### 记录类型切换采用服务端重新查询

记录弹窗仅保留打包类型下拉框，默认选择离线升级包。每次切换均按当前版本和类型映射重新调用对应记录接口，并使用后端返回顺序直接渲染。删除完成、上传完成后，重新加载当前选择的类型。

服务端查询替代本地过滤，可保证不同包族与联网状态之间的结果严格隔离。

### 速度作为上传进度的辅助信息

轮询响应的 `progress.speed` 存在时，进度文字显示百分比和速度；不存在时仅显示描述与百分比。任务完成或失败时以终态文本替换进度文本，不保留可能过期的速度。

### 将安装包提交加入代理长请求路径

Python 代理对升级包提交使用无限等待；安装包提交同样加入该白名单，避免本地代理在后端长期打包时以默认 30 秒超时中断请求。

## 风险与权衡

- [后端记录接口返回分页对象或数组的形式不一致] → 继续使用现有列表归一化处理，并保留接口原始返回顺序。
- [在线包历史记录可能已有云盘地址] → 仅隐藏上传入口，不隐藏已存在的云盘地址和复制操作，避免损失历史可访问数据。
- [用户在包族选择与确认之间改变右侧离线/在线控件] → 将最终包类型在进入确认弹窗时固化，并在确认提交时使用该快照。
- [上传进度响应中没有 `speed`] → 将速度视为可选显示字段，不影响进度条与完成状态。

## 迁移计划

1. 部署前端、API 客户端和代理更新。
2. 验证四类包的提交路径、默认离线升级包记录查询、安装包删除，以及在线包云盘限制。
3. 验证离线安装包上传时显示速度，任务完成后刷新对应记录类型。
4. 若需要回滚，恢复上一版前端静态资源和代理长请求配置；后端接口与历史记录无需迁移。

## 开放问题

- 无。安装包删除、离线安装包云盘上传和上传速度字段已由接口文档确认。
