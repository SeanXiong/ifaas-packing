- [x] 2.3 封装 Git refs 与目标分支 Git 配置查询，覆盖分支不存在、`git_id` 缺失和后端业务错误。
- [x] 2.4 实现 Git URL 规范化及当前仓库与版本服务匹配，兼容 HTTP、HTTPS、SSH 和 `.git` 后缀差异。
- [x] 2.5 实现发布目标检查与重新校验，返回服务存在性、分支存在性、当前配置分支和是否需要切换。
- [x] 2.6 封装系统 B 服务分支修改：读取完整模块、查询目标 `git_id`、提交完整更新 payload 并重新查询验证。
- [x] 2.7 实现 `ifaas-pack` CLI 的项目搜索、版本列表、服务列表、refs 查询、目标检查和发布计划校验命令。

- [x] 2.9 增加共享客户端与 CLI 自动化测试，覆盖分页、鉴权重试、字段裁剪、Git URL 匹配、分支校验和分支修改失败。

## 4. 系统 B 后端：自动打包任务 API

- [ ] 4.1 定义自动打包任务文件 Schema、目录布局、`schemaVersion`、唯一 `taskId` 格式和 `clientRequestId` 幂等映射。
- [ ] 4.2 实现同目录临时文件完整写入、flush 和原子替换，并处理遗留临时文件及损坏记录。
- [ ] 4.3 实现 `POST /api/v1/automation/package-tasks` 的参数校验、认证、任务落盘、幂等查询和 `202 Accepted` 响应。
- [ ] 4.4 将自动任务接入现有打包 Service，保存完整请求快照并禁止复制或分叉 Web 手工打包业务逻辑。
- [ ] 4.5 将 `uploadCloud=true` 的自动任务接入现有 Seafile 上传能力，并把上传状态和结果写回同一任务记录。
- [ ] 4.6 实现 `GET /api/v1/automation/package-tasks/{taskId}`，返回稳定状态、真实阶段、进度、制品、Seafile 地址、MD5 和结构化错误。
- [ ] 4.7 实现进程启动时的非终态任务扫描，对可恢复任务继续执行，对无法安全恢复的任务记录明确中断错误。
- [ ] 4.8 实现后台任务写入前的记录存在性和停止标记检查，防止已清理任务重新创建记录。
- [ ] 4.9 为创建、重复创建、响应丢失重试、精确查询、打包失败、上传失败和重启恢复补充自动化测试。
- [ ] 4.10 提供 OpenAPI/Swagger 契约、curl 示例、默认配置、部署配置项和错误码文档。

## 5. 系统 B 后端：七天清理

- [ ] 5.1 新增自动任务清理配置，默认启用、记录保留 7 天、每 24 小时运行一次，并在系统启动后补跑一次。
- [ ] 5.2 按 `source=AUTOMATION` 和 `createdTime < now - 7 days` 选择清理对象，不对任何任务状态做排除。
- [ ] 5.3 清理执行中任务时先停止后台工作并阻止状态写回，再删除任务记录、进度、幂等映射和临时日志。
- [ ] 5.4 确保清理器不删除手工打包记录、Seafile 云端文件和本地制品文件。
- [ ] 5.5 为成功、失败、创建中、打包中、上传中、恰好 7 天、未满 7 天和手工记录补充清理测试。
- [ ] 5.6 验证清理中断后下一次运行可继续完成，且相同 `clientRequestId` 在旧映射清理后可以创建新任务。

## 6. 构建平台：发布任务与分支切换

- [ ] 6.1 在 `GitLabBuildWatch` SQLite 中新增发布任务、请求快照、分支修改结果、Pipeline、系统 B taskId、制品快照和错误字段及迁移脚本。
- [ ] 6.2 定义发布状态机和合法迁移，覆盖 `CREATED`、`UPDATING_BRANCH`、`READY_TO_PUSH`、构建、打包、上传、成功和各失败终态。
- [ ] 6.3 实现发布任务登记 API/CLI，按 `clientRequestId` 幂等保存已确认的精确 Release Plan。
- [ ] 6.4 登记后调用共享系统 B 客户端执行分支修改，已一致时跳过，验证成功后返回 `READY_TO_PUSH`。
- [ ] 6.5 分支修改失败时保存稳定错误并返回 `BRANCH_UPDATE_FAILED`，禁止任务进入构建等待。
- [ ] 6.6 保存 `previousBranch`、`targetBranch`、是否修改和修改时间用于展示；不得实现并发覆盖检测或自动恢复旧分支。
- [ ] 6.7 实现 `UPDATING_BRANCH` 重启恢复，重新查询目标分支并以幂等方式完成同一分支设置。
- [ ] 6.8 为登记幂等、已一致、修改成功、Git 配置缺失、更新失败、验证失败和重启恢复补充测试。

## 7. 构建平台：构建、打包与结果恢复

- [ ] 7.1 将现有一次性构建监控与发布任务关联，严格使用 GitLab Project ID、branch 和完整 Commit SHA 查询 Pipeline。
- [ ] 7.2 目标 Pipeline 成功时使用 `releaseTaskId` 作为系统 B `clientRequestId` 创建自动打包任务并保存 `packageTaskId`。
- [ ] 7.3 目标 Pipeline 失败、取消或超时时结束发布任务，不创建自动打包任务且不恢复系统 B 分支。
- [ ] 7.4 实现按 `packageTaskId` 有界轮询系统 B，区分真实可用的打包、上传、成功和失败阶段。
- [ ] 7.5 自动任务成功时把包名称、下载地址、Seafile 地址和 MD5 保存到 SQLite 后停止轮询。
- [ ] 7.6 系统 B 返回明确失败时保存失败阶段、错误码和消息；记录因七天策略不存在时标记 `PACKAGE_RECORD_EXPIRED`。
- [ ] 7.7 实现构建等待、创建打包和打包查询阶段的重启恢复，已有 `packageTaskId` 时不得再次创建系统 B 任务。
- [ ] 7.8 为历史成功 Pipeline 不误触发、目标 SHA 成功/失败、创建超时幂等重试、查询恢复、结果快照和记录过期补充测试。
